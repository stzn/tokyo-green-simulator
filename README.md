# Urban Green Twin Tokyo

**都市の自然の解像度を上げ、価値を可視化する。**

東京23区の3D建物（PLATEAU）、都道の街路樹14.4万本、公園を重ね合わせ、都市の緑の「現状」と、屋上・壁面緑化による「将来価値」をブラウザ上で試算するWebGISです。研究室訪問やPoC提案のデモとして使うことを想定しています。

**公開URL**：<https://stzn.github.io/tokyo-green-simulator/>（`main`へのpushでGitHub Actionsが自動デプロイ）

## できること

| 機能 | 内容 |
| --- | --- |
| 3Dベースマップ | PLATEAUの建物を高さ（measuredHeight）で押し出して表示。回転・傾き・ズーム |
| 緑地・樹木レイヤー | 公園ポリゴン、街路樹の3Dピラー（高さ＝樹高、色＝樹種）とヒートマップ。レイヤーごとに表示を切り替えられる |
| 区市町村道の街路樹 | 区道など23区管理の街路樹を路線単位で表示（色＝代表樹種、太さ＝本数）。3,530路線・本数の分かる分で115,096本。クリックで路線名・樹種・本数・所管を確認できる |
| 属性表示 | 樹木（樹種・樹高・幹周・推定樹齢・年間CO2吸収量・路線）、公園（面積・管理者）、建物をクリックで表示 |
| 絞り込み | 樹種（407種、検索つき）と行政区。GPUフィルタのため14万本でも再アップロードしない |
| 緑化シミュレーション | 建物を選び、屋上・壁面緑化率を指定して、表面温度低下・冷房等の電力削減・CO2削減を試算。「緑化する」で屋上と壁面に緑が伸びる演出が入り、エリア合計に加算される |
| 計算根拠の公開 | 「計算方法と出典」から、式・係数・出典リンク、計算に含めていない効果を確認できる |
| 地形 | 地理院の標高データ（DEM10B）で23区の起伏を再現し、建物・街路樹・公園・緑化演出をその標高に乗せる。鉛直方向の誇張はなし（1:1） |
| 表示範囲の集計 | いま地図に映っている範囲の街路樹（都道・区市町村道）の本数と公園の数・面積を集計する。樹種・行政区の絞り込みにも連動し、地図を動かし終えてから更新する |
| シナリオの保存・共有 | 緑化した建物と地図の視点を、この端末に保存（localStorage）したり、共有リンク（URL）にして渡したりできる。リンクを開くと同じ建物が緑化され、同じ視点で始まる |
| 現在地ミニマップ | 東京23区全体の小さな地図を常時表示し、今の表示範囲をエメラルド色の矩形で重ねて示す。パン・ズーム・回転に追従する |

## セットアップ

Node.js **20.19以上または22.12以上**が必要です（Vite 8の要件。v24でも動作確認済み）。`node -v` で確認し、足りない場合は nvm・nodebrew などで切り替えてください（nvm なら `.nvmrc` があるので `nvm use` で切り替わります）。

```bash
npm install
npm run dev        # http://localhost:5173
```

### データの再取得

`public/data/` の生成済みデータはリポジトリに含めています。最新データに更新する場合のみ実行してください。

```bash
npm run data:trees   # 東京都オープンデータ → public/data/trees.json（約1分）
npm run data:parks   # Overpass API → public/data/parks.geojson（混雑状況によって10〜30分）
npm run data:wards   # Overpass API → public/data/wards.geojson（行政界。数分〜十数分）
npm run data:dem     # 地理院標高タイル → public/data/dem/（約1分）
npm run data:city-trees  # 東京都「緑のオープンデータ」 → public/data/city-trees.geojson（約1分）
```

`data:dem` は取得した地理院標高タイルを `scripts/.cache/dem-raw/` に、`data:city-trees` は配布ZIPを `scripts/.cache/city-trees/` に保存し、再実行時はそこから読み直します。`data:parks`／`data:wards` は区ごとのOverpass応答をそれぞれ `scripts/.cache/parks-raw/`／`scripts/.cache/wards-raw/` に保存します。途中で失敗しても再実行すると続きから取得し、変換ルールを変えたときも再取得せずに作り直せます。

## 開発

```bash
npm test             # Vitest（振る舞いテスト）
npm run typecheck    # tsc --noEmit
npm run build
```

テストは **BDD**（振る舞いを先にテストで書き、それから実装する）で書いています。`describe('機能: …')` → `describe('シナリオ: …')` → `it('Given … / When … / Then …')` の形です。WebGLはjsdomで動かないため、次のように範囲を分けています。

- 計算・データ変換・ストア・レイヤー生成関数：単体で検証
- UI：地図（`MapView`）をモックにして、ストア経由の振る舞いを検証
- 実描画：ブラウザで確認

```
src/
  data/cityTrees.ts           区道の街路樹（路線）の読み込み・絞り込み・線への展開・範囲集計
  data/parks.ts               公園ポリゴンの読み込みと範囲集計

  lib/geo.ts                  面積・外周長・リング単純化など（球面近似）
  lib/projection.ts           現在地ミニマップ用の緯度経度→SVG座標の投影

  data/wards.ts               区境界データ（ミニマップ表示用）の読み込み
  store/appStore.ts           状態管理（zustand）
  layers/                     deck.glのレイヤー生成
  components/                 UI
```

## 数値の扱いと既知の制約

- **係数の出典**：`src/lib/simulation/coefficients.ts` の係数は、すべて公的資料で出典を確認済みです（2026年9月）。各係数に資料名・該当箇所・URLを持たせ、`coefficients.spec.ts` で「確認済み・URLあり」を検証しています。

  | 項目 | 値 | 出典 |
  | --- | --- | --- |
  | 屋上の表面温度低下 | 目安15℃／最大23.7℃ | 環境省「ヒートアイランド対策ガイドライン改訂版」H25、国交省 報道発表 H19.8.24 |
  | 壁面の表面温度低下 | 最大10℃ | 同ガイドライン（東京都「壁面緑化ガイドライン」を引用） |
  | 屋上緑化の冷房等の電力削減 | 9.40 kWh/m²・年（5.218 kg-CO2 ÷ 0.555） | 国交省「低炭素まちづくり実践ハンドブック 資料編」H25 |
  | 電力の排出係数 | 0.421 kg-CO2/kWh | 東京電力EP 2024年度 |
  | スギ換算 | 8.8 kg-CO2/本・年 | 林野庁 |
  | 街路樹（高木）1本のCO2吸収 | 39.6 kg-CO2/年（0.0108 t-C） | 日本国温室効果ガスインベントリ報告書2025 表6-53 |
  | 樹齢推定 | 樹種別の回帰式（17樹種） | 国総研「公園樹木管理の高度化に関する研究」H22 表-12 |

- **計算に含めていないもの**：次の5つは、原典に当たったうえで計算に含めていません（2026年9月調査）。定義は `src/lib/simulation/coefficients.ts` の `EXCLUDED_EFFECTS` にあり、画面の「計算方法と出典」にも同じ内容を出しています。

  | 効果 | 確認した資料 | 含めない理由 |
  | --- | --- | --- |
  | 屋上・壁面の植物によるCO2固定 | 日本国温室効果ガスインベントリ報告書2025年 6章 6.8.1（Page 6-62、脚注13） | 国の算定でも都市緑地の生体バイオマスは「高木（樹高3〜5m以上になる樹木）のみ」が対象で、屋上の芝生・地被・低木は計上しない。国と同じ範囲に合わせています |
  | 雨水の一時貯留（流出抑制） | 東京都雨水貯留・浸透施設技術指針（H21）本編・資料編、国交省「低炭素まちづくり実践ハンドブック 資料編」、国交省 屋上緑化・壁面緑化推進の取組 | 技術指針の「屋上貯留」は屋上を貯留施設にするもので、屋上緑化の植栽基盤そのものの貯留量[mm]は示されていません。他の公的資料にも原単位がなく、貯留量は土壌厚・土壌材料・先行降雨で大きく変わるため、代表値を置くと誤差が大きくなります |
  | 壁面緑化による冷房負荷の削減 | 山崎ほか2009『熱的薄い壁体建物の屋上・壁面緑化による冷房負荷低減効果』日本建築学会技術報告集 | 査読付き論文はありますが、断熱のほぼ無い実験棟が対象で、一般建築物に当てはめると過大評価になります |
  | 植栽タイプ（セダム・芝・低中木）による差 | 環境省「ヒートアイランド対策ガイドライン改訂版」3章 No.7・No.8 | セダム系植物は「蒸散量が少なく、対策効果が限定的」、壁面緑化は「樹種や工法によって効果にも違いが見られる」と書かれていますが、いずれも定性的でタイプ別の数値がありません |
  | 周辺気温の低下 | 同ガイドライン 3章 No.6 建物敷地の緑化 図3.27（UCSSシミュレーション） | 緑化率別の気温低下を示した図はありますが、対象が「敷地の緑化」で屋上・壁面緑化ではなく、数値も図から読み取る形でしか示されていません |

- **試算の幅**：屋上緑化の電力削減は、建物ごとの断熱性能を区別せずに代表値（9.40 kWh/m²・年）で計算しています。同ガイドライン 図3.32 によると、東京の業務建物では通年の空調負荷削減率が断熱なし12.4%・断熱25mm 7.1%・断熱50mm 5.0%と2倍以上の幅があり、断熱の薄い古い建物ほど効果が大きく出ます。
- **区市町村道の街路樹**：単木の位置は公開されておらず、路線の線に樹種と本数が付いたデータです。そのため本数から点を並べて1本ずつのように見せることはせず、線のまま表示しています。樹高・幹周が無いので、樹齢とCO2吸収量もこの区分では算定していません。3,530路線のうち**1,059路線は本数が公開されていません**（画面では「不明」と表示し、線は最小の太さで描きます）。なお区ごとの個別公開は杉並区のみで、その配布ページ（`www2.wagmap.jp/suginami/OpenDataDetail?lid=50`）は2026年9月現在404です。
- **エリア集計とシナリオ共有をサーバーなしで実現した理由**：当初はAPI（Hono on Cloud Run）を想定していましたが、必要なデータ（街路樹・区道・公園）はすでにブラウザ上にあり、緑化した建物の状態も画面が持っているため、サーバーを挟む理由がありませんでした。GitHub Pagesの静的配信のまま、運用コストゼロで動きます。代わりに次の制限があります。
  - 共有リンクは**建物の形（外周）ごとURLに入れる**ため、建物が多いと長くなります。緑化の演出が使うのは外周だけなので穴は持たず、約1mの許容誤差で頂点を減らして座標を丸めています。それでもURLが6,000文字を超えると共有リンクは作らず、理由と「この端末に保存」の案内を出します。共有できる棟数の目安は、単純な形（外周8頂点程度）で約14棟、やや複雑（20頂点）で約8棟、複雑（40頂点）で約5棟、かなり複雑（80頂点）で約2棟です（不規則な外周で実測）。1棟なら約800文字です
  - 「この端末に保存」は**その端末・そのブラウザの中だけ**に残ります（プライベートブラウズでは使えません）。端末をまたいで渡すときは共有リンクを使ってください
  - 共有・保存するのは緑化した建物と視点だけで、試算結果は持ちません。開いたときに係数から計算し直すので、係数を更新しても古い値は残りません
  - 集計は表示範囲と重なる路線・公園を数えます。範囲をまたぐ区道の路線や公園は全体の本数・面積を数えるため、範囲の端では実際より多めになります
- **区道の線と地形**：区道の線にも地形の仕組み（TerrainExtension）を付けているため、起動直後の数フレームだけ deck.gl が `shaderInputs` のエラーをコンソールに出します。その後は発生せず、描画・クリックには影響しません（deck.gl 9.4 + MapLibre 5 で確認）。線を地形に貼り付ける drape モードも試しましたが、半透明の地形メッシュに隠れて線が見えなくなるため採っていません。
- **推定値**：樹齢は回帰式のある17樹種だけを推定します（CSVの「サクラ」はソメイヨシノ、「スズカケノキ」はプラタナスの式を適用）。それ以外は「推定式なし」と表示します。CO2吸収量は国の算定に合わせて高木のみを対象とし、中木は「対象外」です。
- **公園の管理者**：OSMの `operator`／`owner` タグを使います。タグが無い場合は、名称に「都立」「区立」とあるときだけ推定し、それ以外は「不明」と表示します（現状、約9割が不明）。区の公園一覧のオープンデータは区によって有無・形式がまちまちで、突き合わせには使えませんでした。
- **公園の範囲**：Overpassの区域検索は区境をまたぐポリゴンも返すため、区外の公園（例: 戸田公園）が一部含まれます。
- **地形データ**：地理院標高タイル（dem_png）は、無効値が `(128,0,0)`、負の標高が2の補数でラップする形式です。deck.glの `elevationDecoder` もMapLibreのraster-demも線形変換しか持てず、そのままでは海域が+83,886mの壁、低地（江東区・江戸川区は画素の6〜7割が負の標高）が+650mの柱になります。そのため取得時に標高へ戻し、線形に復号できる形式（`h = (R*256 + G) * 0.1 - 1000`、無効値は0m）へ詰め替えたタイルを `public/data/dem/` に同梱しています（z=10〜13、最も細かいz=13で約19m/px、合計約4MB）。
- **地形の見せ方**：ベースマップ（MapLibre）自体は平らなままで、deck.glの地形メッシュを半透明で重ねています。MapLibreの `setTerrain` でベースマップも起伏させると、ベースマップもdeck.glのレイヤーも描画されなくなるためです（deck.gl 9.4 + MapLibre 5 で確認）。
- **ヒートマップと地形**：街路樹をヒートマップ表示にすると地形は自動で切れます。ヒートマップは画面上の集計で地形に追従できないうえ、地形の仕組み（TerrainExtension）が有効だとヒートマップ自体が描画されないためです。このときは描画方式もオーバーレイに切り替えています。
- **行政界（ミニマップ）**：現在地ミニマップの表示専用に大きく単純化（Ramer-Douglas-Peucker、許容誤差0.0015度）しており、正確な区境ではありません。
- **建物形状**：タイル境界をまたぐ建物は、ピックしたタイル内の形状で外周長を計算します（屋根面積はPLATEAUの属性値を使うため影響しません）。
- **描画方式**：deck.glのレイヤーをMapLibreのレンダリングに挿し込む interleaved モードで描いています。地形（TerrainExtension）はcanvasを重ねるだけのオーバーレイ方式では効かないためです。以前はこの組み合わせでピッキングが効かず見送っていましたが、現行版では建物・公園・街路樹とも選択できることを確認しています（2026-09 再確認）。MapLibre 6 は deck.gl 9.4 が未対応のため 5 系に固定しています。
- **依存の脆弱性警告**：`npm audit` で、deck.gl geo-layers が間接的に依存する3D Tiles／glTF／画像パーサのDoS系の警告が出ます。本アプリは信頼できるPLATEAUのMVTしか読み込まず、修正版の提示がメジャーダウングレードのため、現時点では受け入れています。
